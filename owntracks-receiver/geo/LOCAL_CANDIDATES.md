# 非公開の本人修正から、近傍GPSの店舗候補を作る（試作・本番未接続）

目的：外部地図APIが未接続でも、ユーザーが年別Excelの「店舗名の修正」シートF列に入力した店名から、別の観測点に **「類似地点・未確認の店舗候補」** を出す。修正済みの店名を別観測の本人確認済み記録に格上げしてはならない。

## 安全な処理順序

1. クラウドの本人所有・非共有の年別Excelを取得し、直前の更新時刻・ファイルIDを控える。機微座標を外部検索サービスへ渡さない。
2. `extract-local-corrections.py` でイベントID、GPS座標、精度、本人修正名の対応を端末／非公開実行環境の作業領域にだけ抽出する。毎回、月シートのイベントIDと年・月を照合する。
3. `plan-local-candidates.mjs` で別イベントの近傍地点を照合する。精度15m以下・距離12m以内が基本。重なる可能性のある複数施設名があれば候補を出さない。本人修正済みの名前だけを参照し、機械推定の候補名は学習・再利用しない。
4. `plan-excel-candidates.mjs` と `apply-candidates-artifact.py` で、修正シートの自動候補D/E/N/Oだけを新しいローカルExcelコピーへ差分反映し、読み戻す。F列本人修正、G/H列表示式、I列イベントIDは絶対に書き換えない。元の各月E列、GPS座標、日時も保持する。
5. 本番ファイルを更新する前に最新のDrive版と本人の追記を再取得し、競合・変更・未確認の場所は保留。保存後に同じDriveファイルIDで再読取一致を確認して初めて成功とみなす。

## 再現方法（データはすべて架空）

```sh
node --test owntracks-receiver/geo/*.test.mjs
python owntracks-receiver/geo/synthetic-end-to-end-test.py
```

本番のOwnTracks送信処理・Render・Google Driveへの自動書込みには **未接続**。CI内のGSI接続検証は公開観光地点の固定座標のみを使用し、個人のGPSデータを送信しない。固定公開地点で実通信が失敗した場合はライブ接続成功と報告しない。

**禁止事項**：抽出したprivate JSONや実ユーザーの座標をGitHub、CIログ、公開サービスに添付しない。修正候補を入店実績として確定しない。勝手な有料API契約、実GPSの大量バッチ外部送信をしない。
