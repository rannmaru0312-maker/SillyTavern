# 年別 Excel 向け GPS 候補反映アダプター（Draft・本番未接続）

## できること
- `place-enrichment.mjs` が **公開地点・プライバシー審査済み** の座標で取得した `automatic_candidate_unverified` のみを受け取り、**イベントID**で既存「店舗名の修正」シートに対応させる。
- `plan-excel-candidates.mjs` は既存セルの値を照合し、候補を D=店名, E=町域住所, N=提供元, O=取得時刻 へ入れる差分計画を作る（変更・衝突は保留）。F=本人修正、G/H=表示式、I=イベントID、月別シートのE列（原記録）を変更しない。
- `apply-candidates-artifact.py` は**ローカルファイルのコピー**に候補を反映して保存後に原本イベントIDと本人修正Fと表示G/Hの式を読み戻して照合する。使用には `artifact_tool` の Python 実行環境が必要。
- テストは架空の地点・架空の名前のみを使い、実ユーザーの住所やGPSデータは外部へ送信しない。

## 実行例

```sh
node --test owntracks-receiver/geo/*.test.mjs
python owntracks-receiver/geo/apply-candidates-artifact.py sample.xlsx mock_plan.json updated.xlsx
```

- 公開OSM Overpassの共有サーバーは利用制限・負荷・継続性の制約がある。Google/Appleの地図APIも料金や適用条件を検証しないまま本番接続しない。
- 自宅、訪問先、医療施設、勤務先などの**機微な地点を外部に一括送信しない**。公的住所候補は番地まで保証しない。実際の店舗利用・到着を証明しない。
- 年別Excelの正本 `生活記録_2026.xlsx` は**変更しない**。まず架空データで試験し、候補列の意味や保護地点分類が確定した段階で本番を検討する。

## 安全上の仕様

1. 本人修正 F列は最優先。候補更新で上書きしない。Event IDの対応を守る。
2. 検索結果は提案値であって「本人がその店に行った」証拠ではない。
3. Excel数式注入 (`=`, `+`, `-`, `@`から始まる文字列等)、制御文字を拒否する。
4. GPSの原本とExcelの出典、観測時刻、本人修正を保持する。新年には新規Excelを作る。
5. 住所の細かい番地や第三者住所は不明なら「未取得」。推測しない。
