# MIYA & KOHARU: 隔離ブラウザー回帰テスト

PR #24 の認証・会話・記憶承認を、架空利用者A/Bと架空のみや/小春で検証する。
既存の人格・設定・記憶、公開済み環境設定、本番には触れない。

## 実行

Node.js 24、ルートと `tests` の依存関係、Chromium が必要。

```sh
npm ci --ignore-scripts
npm ci --ignore-scripts --prefix tests
# インストール済みChromiumを使う場合
MIYA_CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e:miya --prefix tests
# Playwright管理のChromiumがある場合
npm run test:e2e:miya --prefix tests

npm run test:unit --prefix tests -- --runInBand
npm run lint
```

Cloud環境でlocalhost待受がEPERMになる場合、実行ツールの正式な承認付き実行を使う。
ネットワーク設定やTLS検証を解除しない。CIでは既存のPR検証ジョブ内でJestの後に
Chromiumを用意し、UIテストを順次実行する。

## 隔離と観測

- Git管理されたソースだけを一時ディレクトリにコピーする。ignoredデータや
  未追跡の拡張は取り込まない。追跡されたMIYA拡張は、gitignore対象ディレクトリ内でも含める。
- 設定、利用者ストレージ、キャラクターカード、チャット、プラグインの記憶は一時コピー内。
- AIはlocalhostのOpenAI互換モック。ブラウザーから他originへの通信を拒否する。
  API設定は画面で入力する。架空カードには別々の `miya_memory_id` を設定する。
- ブラウザーのフォーム・ボタン・メニューでログイン、会話、承認、ログアウトを操作する。
  テストコードからブラウザー内fetchで代用しない。
- モックへの実リクエスト、UI操作で発生したHTTP応答、一時保存ファイルを補助証拠とする。
  古いCookie再利用の拒否は、UIログアウト後の隔離HTTP要求で確認する。
- スクリーンショット/traceは失敗時のみ、JSON結果は
  `tests/test-results/miya-browser-results.json`。生成物はGitに含めない。
- 成否にかかわらず、起動したアプリ/モックと一時データを終了時に後始末する。

## カバーする範囲と未達範囲

UIテストは無効ログイン拒否、アカウント表示、2キャラクターの会話・ローカルAI応答、
会話の再読み込み/再ログイン、会話からの候補作成、候補表示・重複拒否・承認、
未承認データが長期記憶へ入らないこと、利用者切替、ログアウトを対象とする。

承認済み記憶の永続化は保存ファイルとHTTPテストで検証する。
**承認済み一覧を読むUI、承認済み記憶を後日のAIプロンプトへ取り込む処理、記憶削除UI/APIは
まだないため、これらをUI成功とはしない。** Playwright結果にも未実装の2シナリオをskipとして残す。
組み込みのSummarize拡張はMIYAの候補承認機能とは別物。

`miya-memory-v3-accounts-http.test.js` はAPIとして、候補/承認/読出し、重複409、
偽装利用者IDの無視、別利用者による承認404、不正キャラクターID400、
承認時の偽装characterIdが候補の保存先を変更しないことを検証する。
共通記憶は利用者内だけで共有する仕様であり、そのテストは隔離common.jsonに
架空データを準備する。共通記憶の作成UIが成功したという意味ではない。
有効なキャラクターIDは利用者内の名前空間であり、同じ利用者内のキャラクターごとのACLはない。

P1/P2のストレージ障害、失効、期限延長、sessionTimeout=0、延長とログアウトの競合は
既存Jest/隔離HTTPテストで継続確認する。外部AIの品質・実課金API・複数サーバー構成は対象外。

## 今回の再現と修正

候補作成APIが201を返しても、ページ初回ロード時だけ作られた一覧には候補が現れず、
そのまま画面から承認できなかった。E2Eでは「会話送信→候補201→パネルを開く→候補1件」
の最後の期待が0件で失敗した。

候補作成成功・パネル展開・承認後に同じ一覧再取得処理を使い、古い取得応答が新しい一覧を
上書きしないよう世代番号で制御する。取得失敗時は古い一覧を消してエラーを表示する。
新しい記憶機能や認証方式は追加していない。

初期検証の会話再ログイン失敗は、架空カードに実際のカードが持つ固定chat名を省いた
fixture不備だった。固定chat名を用意して解消。再読み込み後のAPI再接続は既存設定
`auto_connect=false` に従い、Connectボタンから行う。

通常のESLintはthird-party拡張を除外している。変更した拡張を除外なしでも比較し、
既存の書式指摘が27件から26件に減り、新しい種類の指摘がないことと構文正常を確認した。
本体および変更したテストファイルの通常ESLintは別に実行する。

## 運用上の区別

管理用ActionsのGitHub App ID不足は、アプリ/Jest/UIテストの失敗とは分けて報告する。
設定値や認証情報を推測して補わない。PRはDraftを維持し、マージ・デプロイしない。
結果報告では対象コミットSHA、成功/失敗/skip件数、CIと独立レビューの状態を記録する。
UI未達項目があるため、利用者の一連の長期記憶体験が完成したとは扱わない。
