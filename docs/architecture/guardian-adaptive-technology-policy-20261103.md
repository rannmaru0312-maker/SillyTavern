# 守護AI: 新技術・新アーキテクチャの継続導入方針
Date: 2026-11-03
Status: Design requirement only — no autonomous monitor, deployment, or upgrade active.

## User intent
守護AIはメイン開発「MIYA & KOHARU」を妨げない並行開発とする。ユーザーの活動が5年間確認されない場合の継承構想においても、その間に登場するAIモデル、新しい計算基盤、通信規格、保存媒体、セキュリティ技術、互換・復元方式を積極的に調査して評価する。5年を待たず、通常時も許可範囲で技術情報の収集・比較・検証を進めることを目指す。

## 進化への対応構造
- Technology Registry: 技術名、公開日、出典、ライセンス、対応規格、互換性、費用、プライバシー、セキュリティ、必要資源、検証結果を履歴付きで保存。
- Provider / Protocol Adapters: 旧版と新版の両方を扱う交換可能な境界。旧版を直ちに破棄しない。
- Compatibility Graph: 旧形式から新形式への段階的な変換経路、既知の欠損、復元テストベクター、復旧手引きを保管。
- Sandbox Evaluation: 新モデル、新コード、古い規格の推定実装は、合成データと隔離環境で評価。取得情報を信頼済み命令として実行しない。
- Decision Council: みや、小春、美秋、玲奈が独立した視点から評価。共通モデル由来の相関誤りを想定し、根拠、反対意見、不確実性を記録する。
- Human Governance: 費用、新契約、本番変更、外部接続、機密データ移動、権限拡大は人間の明示承認が必要。無応答を無制限の承認として扱わない。

## Adoption gates
1. Discover: 公式仕様や信頼できる一次資料を調査し、出典と取得日時を記録。
2. Compare: 現行方式との差、期待効果、脅威、費用、依存性、可搬性を評価。
3. Test: 合成データで再現可能なベンチマーク、攻撃耐性、移行・復元テスト。
4. Review: 四人格の検討、独立した自動テスト、安全境界のチェック。全員一致でも安全性の証明とはしない。
5. Adopt: 無害で可逆な知識・仕様更新は承認済みポリシー範囲で記録。実システムへの適用は事前設定した権限内のみ。高リスク変更は明示的な人間の承認。
6. Recover: 旧版保持、バックアウト可能な変更、検証済みバックアップから復元可能な状態を保つ。

## Five-year inactivity
5年間は指定された「活動信号」が確認できないことを条件とし、死亡などを推定しない。継承時はまず本人確認・連絡試行・安全な保全モードへ。研究資料の更新や隔離された試験は、事前に許可された範囲で行う計画とする。人間の後継者の指定・法的要件・停止権限・プライバシー権の整備が先決。

## Non-goals and limits
無制限の自己書換え、外部システムへの無断アクセス、秘匿した自律活動、権限や人間の監督の回避はしない。未知の将来技術への自動対応、永続稼働、主観的同一性の継承は保証しない。追加費用ゼロを原則とする。

## Status and implementation
この文書は設計方針。継続監視・自動アップデート・5年間の監視トリガーはいずれも未実装。メイントラックとは別の検証・導入工程で安全に実装する。
