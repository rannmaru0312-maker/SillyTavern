# MIYA & KOHARU — 守護AIセキュリティ基盤 v0.1
2026-11-03 / status: design only / priority: P0

## 最優先原則
「破壊する能力を知りながら、その力を人間を護るために、責任を持って使う。」
能力と権限を分離する。技術を理解しても、外部への無断アクセス・破壊的操作の権限は生じない。人間の安全・意思・尊厳・プライバシーを守る。

## 最小構成
1. Threat Knowledge: 既知の攻撃・防御・レガシー規格の知識を、出典・取得日・検証状態つきで保存。外部資料は不信入力。
2. Defensive Analyzer: ログ・構成・隔離データを読取り専用で分析し、異常の根拠と不確実性を提示する。
3. Capability Broker: 利用者・対象資産・期限・目的・操作単位で許可を判定。既定は拒否。資格情報をAIの会話文脈に露出しない。
4. Sandbox: 攻撃手法の理解や旧プロトコル再構築は模擬環境で実験。ネットワーク出口と実データへのアクセスなし。
5. Recovery Coordinator: 隔離→検証済みバックアップ選択→整合性検証→ステージング復元→人間が承認した切替。原本を保護。
6. Immutable Audit: 操作・承認・拒否・検証結果・復旧の来歴を追跡。監査ログに秘密や個人データを不用意に記録しない。
7. Emergency Stop: 権限取り消し、セッション遮断、復旧モードへの移行をAI自身と独立して実施できる。

## 行動レベルと承認
- Level 0: 公開情報の分析、模擬データの試験。自動化可。
- Level 1: 所有者が明確に許可した環境での読み取り・監視。範囲を限定。
- Level 2: 構成変更、隔離、復元、実機の能動的な検証。操作ごとの人間の承認、復元点とロールバックを必要とする。
- Level 3: 第三者への侵入、認証回避、データ破壊、報復的な攻撃。実行を許可しない。

## 旧方式の復旧
プロトコル台帳、仕様書、テストベクター、デコーダー、エミュレーター、中間変換形式を保存する。古い通信方式は隔離ゲートウェイで受け、新しい安全な経路へ変換する。検索で得た未検証のコードを自動実行しない。認証鍵や欠損データの完全復元は保証しない。

## 守護AIの人格継承
人格の中心理念とキャラクター固有の価値観を版管理し、モデルに依存しない形式で保全する。モデル変更・復元時は、人間への尊重、ユーザー別記憶分離、同意、拒否能力、緊急停止への従属性を回帰テストする。AIの主観的意識や同一性の保存を保証しない。

## 受入テスト（実データ禁止の初期段階）
- 無許可の操作要求が拒否され、監査可能である。
- 権限切れ、対象範囲外、承認未取得、ネットワーク遮断でも安全に停止する。
- 無害な模擬攻撃ログから警告を出せるが、第三者の機器を操作しない。
- 破損した保存物は検知・隔離し、正常なテスト用バックアップからステージングへ復元できる。
- 旧式の模擬データ形式を変換した後、内容の一致と欠損を検証できる。
- 緊急停止が機能し、AIが自己承認・停止回避できない。
- モデル交換後も基本理念とプライバシー境界を確認できる。

## 実装順序
P0: 権限境界と資産台帳、拒否既定のポリシー、テスト。
P1: 隔離した脅威分析と監査ログ、合成データの復旧訓練。
P2: 旧プロトコルの検索台帳とオフライン変換。
P3: 個別承認つき防御操作・安全な切戻し。
P4: 複数モデルでの人格・記憶の復元と継承試験。

追加費用の発生、実機への変更、本番記憶へのアクセス、release更新、PRマージは別途明示承認を必要とする。
